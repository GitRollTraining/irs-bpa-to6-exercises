## What the check runs

The check builds a temporary lab, as the reset builds it, with the course's run 2 files from `~/practice/lab-states/run2/`. It runs the done-when's command in that lab, and there the command must pass. Then it runs the command on two more copies, each with a wrong extractor from `../files/wrong-run-2/`. One extractor accepts every reply that is JSON. The other puts 0 in place of null. The command must fail on each. So a command that names a test that only your prompt asks for fails on the course's run 2.

The check does not accept a reply that must fail if the schema accepts it, such as one with `amount_in_question` null or 0. From the reply alone, the function cannot tell that 0 is wrong for note 0102.

The check does not accept run 1's "Do not call any model." in run 2's Constraints. The Goal's function sends each note to the model, so the rule must name the tests.

The start already denies Claude Code edits to `tests/test_schema.py`, in `.claude/settings.json`. The prompt still keeps the agent out of it. Codex does not read that file, and the prompt gives the bounds of the task to each agent.

## For the debrief

- A run that adds a field changes the schema. Its Constraints then let the agent change `schema/output.schema.json` and `tests/test_schema.py`, and its done-when runs run 1's tests too.
- The done-when runs the tests that the agent writes. An agent that writes weak tests, or changes them until they pass, passes it. The done-when also cannot judge the words of `issue` or `next_action`. The model chooses its words, and a new run can choose others. Section 5.2 takes this up.
- The third question has no kept answer. Each learner answers from their own work.
